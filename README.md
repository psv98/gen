# Icon Studio

Веб-приложение для работы с библиотекой из 500 оригинальных SVG-иконок: поиск, настройка обводки, фона и холста, экспорт в SVG, PNG и JPEG, пакетная выгрузка в ZIP.

Приложение статическое: не нужен сервер, база данных, регистрация или внешние API. Все иконки и метаданные лежат в репозитории.

## Что внутри

- 500 иконок в 10 категориях по 50: право, медиа, технологии, медицина, финансы, документы и учёт, государство и дипломатия, НКО, безопасность и оборона, бизнес и маркетинг.
- Единая сетка 24×24, обводка 1.8, `round` для концов и соединений, `currentColor`, без заливок.
- Названия, описания и ключевые слова на русском, украинском и английском.
- Редактор: толщина, цвет, концы и соединения линий; фон (нет, цвет, линейный и радиальный градиент) и форма фона (квадрат, скругление, круг, сквиркл на основе суперэллипса); размер холста с блокировкой пропорций, размер иконки, отступы, выравнивание, поворот, отражение; тень.
- 8 встроенных пресетов и сохранение своих; избранное, недавние, коллекции. Всё хранится в `localStorage`.
- Отмена и повтор (Ctrl/⌘+Z, Ctrl/⌘+Shift+Z), режим сравнения с оригиналом, превью в 16–64 px, сетка 24×24 поверх холста, режим фокусировки, светлая и тёмная тема.
- Экспорт: SVG (по желанию с `currentColor`), PNG 64–4096 px или свой размер, JPEG с качеством и цветом подложки, копирование SVG и PNG в буфер, ZIP для нескольких иконок.
- Командная палитра (Ctrl/⌘+K): переход к любой иконке, категории или команде с клавиатуры.
- «Код и файлы»: копирование иконки как React-компонента (обводка в props), Data URI, CSS-класса, SVG с `currentColor`; скачивание исходника 24×24.
- Похожие иконки в инспекторе, плотность сетки (S/M/L), просмотр всей библиотеки с текущей толщиной и типом линий, перетаскивание иконки из сетки в другие программы как SVG-файла (Chrome, Edge).
- Готовые форматы холста: favicon, иконка приложения, пост и сторис для соцсетей, обложка ссылки, слайд 16:9.
- Пакетный экспорт в ZIP или в один SVG-спрайт с `<symbol>`.
- Icon Quality Gallery (`#quality`): контактные листы по категориям в 16, 24, 32, 64 px и на толщинах 0.75 / 1.8 / проверенный максимум / 3.5, плюс отчёт `validate-icons`.

## Быстрый старт

Нужен Node.js 22.18 или новее (скрипты импортируют `.ts`-модуль без сборки).

```bash
npm install
npm run dev          # http://localhost:5173
npm run build        # production-сборка в dist/
npm run preview      # локальный просмотр dist/ на http://localhost:4173
```

## Проверки и тесты

```bash
npm run validate-icons   # 15 проверок библиотеки, отчёт в src/data/qa-report.json
npm test                 # Vitest: сборка SVG, поиск, история, целостность библиотеки
npm run test:e2e         # Playwright: поиск, редактирование, экспорт, ZIP, сохранение
npm run sheets           # PNG-контактные листы в qa-sheets/ (нужен rsvg-convert)
```

Для e2e нужен браузер: `npx playwright install chromium` или путь к Chrome в `CHROME_PATH`, например `CHROME_PATH=/usr/bin/google-chrome npm run test:e2e`.

`validate-icons` проверяет: ровно 500 файлов; по 50 в категории; уникальность ID и slug; соответствие файлов реестру и наличие метаданных на трёх языках; валидность XML; `viewBox="0 0 24 24"`; отсутствие внешних ссылок; отсутствие скриптов, `style`, `foreignObject`, обработчиков событий; непустую геометрию; отсутствие точных дубликатов геометрии; что цвет задаётся только через `currentColor` на корне; что толщина и тип линий задаются только на корне и ни один дочерний `transform` не масштабирует обводку; что геометрия лежит в пределах 1–23 (предупреждение при выходе за 2–22); что каждая иконка собирается в SVG с градиентом, сквирклом, тенью и поворотом и растеризуется. Проблемы выводятся с путём к файлу и ID.

## MCP-сервер для Claude

В папке `mcp/` лежит MCP-сервер: через него Claude ищет иконки по смыслу и получает готовые SVG или PNG нужного цвета и размера. Подключение к Claude Desktop, Claude Code и как коннектор в claude.ai описано в [docs/MCP.md](docs/MCP.md).

```bash
npm --prefix mcp install
npm run mcp:test      # проверка всех инструментов
npm run mcp           # stdio-сервер
npm run mcp:http      # HTTP-сервер на :8787/mcp
```

## Новые иконки от внешнего исполнителя

[docs/ICON-BRIEF.md](docs/ICON-BRIEF.md) — бриф для модели или дизайнера: сетка, правила обводки, формат ZIP и `manifest.json`, пример партии из 50 юридических концепций. Полученный архив проверяется и добавляется командой:

```bash
node scripts/import-icons.mjs batch.zip --category legal --dry   # только отчёт
node scripts/import-icons.mjs batch.zip --category legal         # добавить принятые
```

Скрипт приводит SVG к формату библиотеки и отклоняет файлы с неправильным viewBox, заливками, масштабирующими трансформациями, слишком тесными элементами, дубликатами геометрии и slug.

## Как устроена библиотека

```
icons-src/<категория>.mjs   исходники: метаданные и геометрия каждой иконки
icons-src/categories.mjs    список категорий и общие атрибуты корня SVG
public/icons/<категория>/   500 самостоятельных SVG-файлов
src/data/icons-manifest.json  реестр концепций: ID, slug, названия, описание, ключевые слова, теги
src/data/registry.json      компактный каталог для приложения (генерируется)
scripts/emit-icons.mjs      icons-src → SVG-файлы + манифест
scripts/build-registry.mjs  SVG-файлы + манифест → registry.json (+ безопасный диапазон толщины)
scripts/validate-icons.mjs  контроль качества
scripts/import-icons.mjs    импорт SVG из папки или ZIP
scripts/lib/shift.mjs       оптическое центрирование (перенос координат)
public/api/registry.json    каталог для внешних инструментов (MCP)
mcp/                        MCP-сервер
scripts/lib/geometry.mjs    разбор и дискретизация SVG-примитивов
```

Приложение не импортирует иконки по одной: оно читает `registry.json`, а сетка библиотеки виртуализирована, поэтому каталог в несколько тысяч иконок не замедлит интерфейс.

### Добавить иконку

1. Добавьте запись в нужный `icons-src/<категория>.mjs`:
   ```js
   ['slug', 'Название|Назва|Name', 'Описание идеи', 'ключ,слова|ключові,слова|key,words', 'tag',
    '<path d="…"/>'],
   ```
   Рисуйте в сетке 24×24 внутри поля 2–22, только обводкой, без `stroke`, `fill`, `stroke-width` и масштабирующих `transform` на элементах.
2. `npm run icons` — сгенерирует SVG, манифест и каталог.
3. `npm run validate-icons` и `npm run sheets <категория>` — проверьте отчёт и посмотрите контактный лист.

Если меняете количество иконок, поправьте `EXPECTED_TOTAL` и `PER_CATEGORY` в `scripts/validate-icons.mjs`.

Можно положить готовый SVG прямо в `public/icons/<категория>/` и описать его в `icons-manifest.json`; `npm run icons:registry` подхватит файл. Но следующий `npm run icons:emit` перезапишет папки из `icons-src`, поэтому основной путь — через исходники.

## Параметры SVG

Каждая иконка хранится так:

```xml
<svg xmlns="http://www.w3.org/2000/svg" width="24" height="24" viewBox="0 0 24 24"
     fill="none" stroke="currentColor" stroke-width="1.8" stroke-linecap="round" stroke-linejoin="round">
  …
</svg>
```

Все параметры обводки наследуются от корня, поэтому редактор меняет толщину, цвет, концы и соединения у геометрии, а не масштабирует картинку. Рабочий диапазон толщины — 0.75–3.5 в координатах сетки 24×24.

У каждой иконки есть свой проверенный максимум (`s` в `registry.json`), он отмечен на слайдере. Он считается эвристикой: берётся наименьший зазор между элементами, которые видны раздельно при 1.8; наименьший внутренний размер замкнутых контуров; и запас до края области. Сейчас 157 иконок проверены до 3.5, 106 — до 3.0–3.5, 125 — до 2.4–3.0, 112 — ниже 2.4. Выше этого значения линии иконки могут сливаться, и редактор об этом предупреждает. Эвристика не оценивает удобочитаемость: при толщине больше 2.6 мелкие детали части иконок становятся плотными, это видно в Quality Gallery.

Холст задаётся в пикселях. Иконка всегда масштабируется равномерно, поэтому смена размеров холста не искажает её пропорции. Растровый экспорт пересобирает SVG в целевом разрешении и рисует его на `<canvas>`, а не масштабирует превью.

Ограничения экспорта:
- Тень записывается фильтром `feDropShadow`. Браузеры, Figma и Inkscape его читают; старые версии Illustrator могут не импортировать фильтр.
- JPEG не поддерживает прозрачность, поэтому прозрачные области заливаются выбранным цветом подложки.
- Копирование PNG в буфер работает в браузерах с `ClipboardItem` (Chrome, Edge, Safari, новые Firefox). Если API нет, кнопка неактивна.

## Развёртывание

Сборка использует относительные пути (`base: './'`) и hash-маршрутизацию, поэтому `dist/` можно положить на любой статический хостинг.

В репозитории есть `.github/workflows/deploy.yml`: при пуше в `main` он проверяет иконки, запускает тесты, собирает проект и публикует `dist/` в ветку `gh-pages`. Чтобы сайт открывался по адресу `https://<пользователь>.github.io/gen/`, в настройках репозитория выберите Settings → Pages → Source: Deploy from a branch → `gh-pages` / root.

`Ctrl/⌘+K` палитра · `/` поиск · `←` `→` соседняя иконка · `S` в избранное · `G` сетка · `C` сравнение · `F` фокус · `+` `−` `0` `1` масштаб · `E` экспорт · `Ctrl/⌘+Shift+C` копировать SVG · `?` справка.

## Локализация

Основной язык интерфейса — русский (`src/i18n/ru.ts`). Чтобы добавить украинский или английский, создайте `uk.ts` / `en.ts` с теми же ключами и зарегистрируйте их в `src/i18n/index.ts`. Названия иконок на трёх языках уже есть в каталоге; поиск работает на всех трёх.

## Планы

MCP-сервер уже есть (`mcp/`). Пока не реализованы генератор иконок на основе ИИ, плагин для Figma, REST API и облачные коллекции; статический каталог `api/registry.json` на GitHub Pages можно использовать как основу для них.
